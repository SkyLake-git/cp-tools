# cp-tools

競技プログラミング用のツール群


> [!IMPORTANT]
> このプロジェクトは作成中 (WIP) であり、不具合や未実装の機能が含まれます。<br>

# 使い方

## 0. 環境

### 必須

- Rust の実行環境: [インストール (公式サイト)](https://rust-lang.org/ja/tools/install/)

### 推奨

- Linux の場合は、認証情報マネージャ (gnome-keyring など)

## 1. インストール

```shell
cargo install --git https://github.com/SkyLake-git/cp-tools
```

更新の際は、 `cargo-update` を使うか再インストールしてください。

## 2. 初期設定

プロジェクトディレクトリで以下コマンドを実行してください<br>
ディレクトリ構成に特に指定はありません。<br>

```shell
cp-tools init
```

成功すれば、設定ファイルが入った `.cp-tools` ディレクトリが生成されます。<br>

## 3. 設定の変更

**現在はコマンドにより設定を変更する機能はないため、手動で変更してください。**<br>
**(最低限必要な項目については追加する予定です)**<br>

[設定項目](#設定項目) を参考に、 `.cp-tools/settings.toml` を編集してください。<br>
この先から、環境に合わせて設定を変更している前提で進めます。

## 4. コンテストサイトにログイン

以下コマンドを実行すると、コンテストサイトに合わせてログインに必要な情報を入力するよう求められるため、指示に従ってください。<br>

```shell
cp-tools login
```

入力後、ログインに成功すれば `Succeeded` と表示されるはずです。<br><br>
入力した認証情報は、お使いのデバイスの認証情報マネージャに保存されます。(Windows は 資格情報マネージャ)<br>
`--dotenv` オプションを付けることで `.env` ファイルに保存できます。
(デバイスに認証情報マネージャがない場合に代わりに使用できます)<br>

### AtCoder

AtCoder にログイン済みのブラウザで開発者ツールを開き、 アプリケーション > Cookie > https://atcoder.jp > REVEL_SESSION
にある値が入力すべき情報です。コピーして貼り付けてください。(「デコードされたURLを表示」はオフにしてください)

## 5. 解く問題を設定する

以下コマンドを実行すると、問題ページをスクレイピングしてテストケースを保存し、提出や提出結果の確認、テストができるようになります。

```shell
cp-tools start [task_id: String]
```

例 (ABC484 の A問題):<br>

```shell
cp-tools start abc484_a
```

または

```shell
cp-tools start
cp-tools |      Task ID : abc484_a
```

(`task_id` を省略すると、ユーザーに入力を求めます)<br>

## 6. テストケースを検証する

以下コマンドを実行すると、全てのテストケースに対してあなたのプログラムを実行します。<br>
ビルドが必要な言語を使用している場合、自動でビルドされないため手動でビルドしてください。

```shell
cp-tools test
```

## 7. 提出する

以下コマンドを実行すると、 [テストケースを全て検証](#6-テストケースを検証する) し、全て正答だった場合にコードをフォーマットしてから提出します。

```shell
cp-tools submit
```

# 設定項目

## 1. 一般設定

### `[general]`

| キー                     | 説明                                                      | デフォルト値 | 設定可能な値 |
|--------------------------|-----------------------------------------------------------|--------------|--------------|
| `contest_type`           | コンテストサイトの種類                                    | `AtCoder`    | `AtCoder`    |
| `language`               | 使用するプログラミング言語                                | `"none"`     | `"cpp_gcc"`  |
| `workspace_delay_millis` | ワークスペースを使うコマンドの実行に遅延を発生させる (ms) | `0`          |              |

> [!NOTE]
> `workspace_delay_millis` は通常は使用しないでください。<br>
> **特定の用途** のために使用されます

## 2. パス設定

### `[paths]`

| キー         | 説明                           | デフォルト値              |
|--------------|--------------------------------|---------------------------|
| `source`     | プログラムのソースファイルパス | `"./source_path.ext"`     |
| `executable` | プログラムの実行ファイルパス   | `"./executable_file.exe"` |

### `[format.out]`

| キー          | 説明                                       | デフォルト値 | 設定可能な値        |
|---------------|--------------------------------------------|--------------|---------------------|
| `method`      | フォーマッタを実行した際の出力先を指定する | `Clipboard`  | `Clipboard`, `File` |
| `target_file` | ファイルに出力する場合の対象ファイルパス   | `null`       |                     |

### `[format.cpp]`

| キー                   | 説明                                                                                                                                                                                                                        | デフォルト値 |
|------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------|
| `expand_include`       | GCC コンパイラのプリプロセス機能を使用して標準ライブラリ、[ACL](https://github.com/atcoder/ac-library) 以外のライブラリをコード内に展開する<br>プリプロセスの際には、 `ONLINE_JUDGE` と `ATCODER` を define します。        | `false`      |
| `expand_library_paths` | `expand_include` 機能での include 検索パスを追加する(複数指定可能)<br>(当該ライブラリが含まれるディレクトリを指定する)<br>`#include "lib/foo.hpp"` などとしている場合、このソースファイルがあるディレクトリを指定すればよい | `[]`         |

> [!WARNING]
> `expand_include` 設定を有効にする場合は以下の点に留意してください
> - プリプロセス機能を使用しているためマクロ展開などが行われます。
> - 当該設定を有効にした後は初期処理が必要になるため環境によっては初回フォーマットに時間がかかります。
> - 初期処理によって数千の空ファイルが作成されます。 (`purge` コマンドで削除可能)

## 4. テスト設定

### `[tester]`

| キー              | 説明                                                                    | デフォルト値 |
|-------------------|-------------------------------------------------------------------------|--------------|
| `timeout_margin`  | 実行時間制限を超過してから、プログラムを強制終了するまでの猶予時間 (ms) | `500`        |
| `error_threshold` | 許容する絶対誤差または相対誤差の閾値 (出力例が浮動小数点の場合)         | `1e-6`       |

## 5. AtCoder 設定

### `[atcoder]`

| キー                    | 説明                                               | デフォルト値 |
|-------------------------|----------------------------------------------------|--------------|
| `watch_interval_millis` | 提出結果の更新間隔 (ms)<br>1000 以下にはできません | `2000`       |

## 6. 検証設定

ルール違反やマナー違反になってしまう行為を可能な限り防ぐ機能群です。<br>
現在実装されていません (wip)

### `[validation]`

| キー                    | 説明                                                     | デフォルト値 |
|-------------------------|----------------------------------------------------------|--------------|
| `check_same_submission` | 現在取り組んでいる問題の中での同一コードの提出を検証する | `true`       |

### `[validation.git]`

主に [AtCoder の生成AI対策ルール](https://info.atcoder.jp/entry/llm-rules-ja)
におけるライブラリの事前公開に関する項目のための検証です<br>

| キー                        | 説明                                                 | デフォルト値 |
|-----------------------------|------------------------------------------------------|--------------|
| `check_uncommitted_changes` | 未コミットのファイルがないか検証する                 | `true`       |
| `check_unpunshed_commits`   | リモートに push されていないコミットがないか検証する | `true`       |
| `target_paths`              | 対象となる Git リポジトリのディレクトリ (複数指定可) | `[]`         |
| `run_every_submit`          | 提出するたびにこの検証を実行します                   | `false`      |
